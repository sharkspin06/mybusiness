2. Layout rules

Desktop ≥ 1024 px

  • Left sidebar 240 px, grey surface; main nav, Pinned, Settings, user
  • Top bar 56 px: breadcrumb, search, New, notifications
  • Work area: max 1280 px, 32 px gutters, 24 px between blocks
  • Page header: title + count on the left, one primary action on the right
  • Detail pages: main column + 320 px side panel

Tablet 768–1023 px

  • Sidebar collapses to a 64 px icon rail; opens as an overlay
  • Side panels drop below the main column
  • Tables keep columns, scroll sideways inside their card
  • Calendar week view kept; month shows dots plus count

Phone < 768 px (iPhone first)

  • Bottom tab bar: Home, Customers, Quotes, Calendar, More (Tasks, Documents, Settings)
  • Top bar 56 px: back or logo, title, search, +
  • Tap targets ≥ 44 px, 16 px inputs (no iOS zoom), safe-area padding
  • Tables become stacked rows; builder gets a sticky total + PDF / WhatsApp bar
  • Week view becomes a day strip + agenda

4. Patterns taken from Coda's public pages

  • Each page starts with a title, a short line of context, then the content blocks
  • Sections have a heading plus an "Add …" action next to it
  • Saved views as tabs above a table (All / By status), filter chips below, search on the right
  • "New row" at the end of a table; status shown as coloured pills
  • Phone: bottom tab bar with 4 pages + More, back arrow in a compact top bar

Only these structural ideas are reused. Colours, logo, type, icons, illustrations and code are all our own: white and teal, Inter, line icons.

5. Singapore formats & rules

  • Currency SGD, shown as S$1,234.50; 2 decimals; amounts right-aligned
  • GST 9% on (subtotal − discount) when the business is GST-registered; turned off otherwise
  • Dates DD/MM/YYYY; 24-hour time; week starts Monday
  • Phones +65 XXXX XXXX; WhatsApp links use the +65 number
  • Addresses: Blk, street, #unit, Singapore 6-digit postal code; UEN on documents
  • Quote numbers Q-YYYY-NNNN, invoices INV-YYYY-NNNN

Not in this phase

Sample data only: no backend, database, logins, saving, real PDF or WhatsApp sending. After approval, Phase 2 builds the app shell (React + TypeScript + Tailwind) with these tokens, then one section at a time, starting with Customers.
